# 08 — Troubleshooting guide

Real errors you'll actually hit, with an example message, the likely
cause, and the fix. If you hit something not listed here, check the
per-lesson "How it breaks" table first (each `tutorial/*/README.md`
section 8), then this page.

---

### 1. "running scripts is disabled on this system"
```
File ...\scripts\setup.ps1 cannot be loaded because running scripts is
disabled on this system.
```
**Cause:** Windows PowerShell's execution policy blocks unsigned scripts
by default.
**Fix:**
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
Then re-run the script. This only affects the current PowerShell window.

---

### 2. `ModuleNotFoundError: No module named 'aisets'`
```
Traceback (most recent call last):
  File "examples\01_skill_hello.py", line 10, in <module>
    from aisets.config import load_settings
ModuleNotFoundError: No module named 'aisets'
```
**Cause:** you ran `python examples\01_skill_hello.py` directly instead
of through `scripts\run-example.ps1`, so `PYTHONPATH` was never set to
`src\`.
**Fix:** use `.\scripts\run-example.ps1 01_skill_hello`, or set it
yourself: `$env:PYTHONPATH = "src"`.

---

### 3. `ConfigError: LLM_BACKEND=claude but ANTHROPIC_API_KEY is empty`
**Cause:** you switched `.env`'s `LLM_BACKEND` to `claude` but didn't set
a real key.
**Fix:** either paste a real key into `ANTHROPIC_API_KEY` in `.env`, or
set `LLM_BACKEND=fake` to go back to offline mode.

---

### 4. `aisets.llm.errors.LLMError: FakeLLM: no scripted response for this call`
```
LLMError: FakeLLM: no scripted response for this call. Last message
started with: '<ticket>My payment failed...'
```
**Cause:** your test/example makes a model call that wasn't scripted —
either you forgot to `queue_json(...)`/`add_rule(...)`, or your code
makes MORE calls than you scripted (e.g. a retry you didn't account for).
**Fix:** count exactly how many `complete()`/`complete_json()` calls your
code path makes and queue that many responses, in order. See
`docs/05-testing-ai-code.md`.

---

### 5. `aisets.llm.errors.BadOutput: ... did not match schema ... even after one retry`
**Cause:** the model's (or your scripted FakeLLM's) output didn't match
the required Pydantic schema, twice in a row.
**Fix:** if this is a scripted test, check your `queue_json` payload
matches the schema exactly (field names, types, enum values). If this is
against a REAL model, the prompt or schema likely needs clarifying — see
`docs/04-prompting-guide.md`.

---

### 6. `pydantic_core.ValidationError` when validating a tool's arguments
```
ToolError: invalid arguments for tool 'query_orders': 1 validation error
for query_orders_Args
limit
  Input should be a valid integer [type=int_parsing, input_value='five', ...]
```
**Cause:** the model called a tool with an argument that doesn't match
the type hint you declared on the underlying Python function.
**Fix:** this is CAUGHT and fed back to the model as an observation (see
`tutorial/03-agents/DECISIONS.md` D-303) — the agent should try again with
valid arguments. If it keeps failing, tighten the tool's docstring to be
explicit about the expected type/format.

---

### 7. `sqlite3.OperationalError: no such table: orders`
**Cause:** `data/orders.db` doesn't exist yet, or points at a stale/empty file.
**Fix:** `python data\seed_data.py` (regenerates all sample data,
deterministically).

---

### 8. `sqlite3.OperationalError: no such table: agent_facts` (LongTermMemory)
**Cause:** you're pointing `LongTermMemory` at a path where the schema was
never created — this shouldn't normally happen since `__init__` calls
`_ensure_schema()`, but can occur if two processes race to create the
file on a network drive.
**Fix:** delete the stale file and let `LongTermMemory` recreate it; avoid
network-drive paths for this kind of local SQLite file.

---

### 9. Case-study data missing
```
AssertionError: Run 'python data/seed_data.py' first
```
or the case study raises a file-not-found error for `data/case_study/easy/app.log`.
**Cause:** the case study's variant data is generated by a SEPARATE
script from the main sample data.
**Fix:** `python data\case_study\build_case_study_data.py`.

---

### 10. `pytest` collects 0 items / can't find tests
**Cause:** you ran `pytest` from the wrong directory, or `PYTHONPATH`
isn't set so `import aisets` fails during collection, silently dropping
the file.
**Fix:** always use `.\scripts\test.ps1` (sets `PYTHONPATH` and runs from
the project root) instead of a bare `pytest` invocation.

---

### 11. Coverage report shows 0% for a file you know is tested
**Cause:** stale `.coverage` data from a previous partial run, or you ran
a single test file directly with `python -m pytest tests\unit\test_x.py`
without `--cov`, then a later combined report got confused.
**Fix:** delete `.coverage` and re-run `.\scripts\test.ps1` for a clean report.

---

### 12. `uvicorn` / example 16's API server: "address already in use"
```
ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8100)
```
**Cause:** a previous run of the server is still running in another
terminal/background process.
**Fix:** find and stop the earlier process, or change the port in
`examples\16_serve_agent_api.py`'s `uvicorn.run(..., port=8100)`.

---

### 13. `httpx`/FastAPI TestClient `StarletteDeprecationWarning`
```
StarletteDeprecationWarning: Using `httpx` with `starlette.testclient` is
deprecated; install `httpx2` instead.
```
**Cause:** a version-skew warning between `fastapi`/`starlette`/`httpx` —
harmless for this project's purposes as of writing.
**Fix:** safe to ignore for now; if it becomes a hard error in a future
`fastapi` release, check the release notes and update the pinned version
in `pyproject.toml`.

---

### 14. An agent stops with `stopped_reason == "loop_detected"` unexpectedly
**Cause:** the model called the exact same tool with the exact same
arguments twice in a row — often because the available tools genuinely
can't answer the question, or the system prompt doesn't make it clear
when to stop investigating and answer.
**Fix:** check `result.steps` for the repeated call; consider whether a
different/additional tool is needed, or clarify the system prompt's
"when you have enough information, answer" instruction.

---

### 15. An agent stops with `stopped_reason == "budget_exhausted"`
**Cause:** `max_steps` (Milestone 5) or `max_attempts` (Milestone 8) was
too low for the question, OR the investigation genuinely isn't converging.
**Fix:** don't just raise the budget — check `result.steps`/the Critic's
`missing` list first for a pattern (see `docs/07-cost-and-latency.md`
before raising any budget, since it directly multiplies worst-case cost).

---

### 16. An escalated write action never executes even though it "should"
**Cause:** `EscalationGate.records` shows `decided_by="no_human_available"`
— by design (`tutorial/04-agentic/DECISIONS.md` D-404), a missing
`human_approve` callback defaults to DENY, not silent approval.
**Fix:** wire up a real human-approval mechanism (a UI, a Slack
confirmation, a CLI prompt) rather than treating this as a bug to route around.

---

### 17. Windows path errors (`\` vs `/`) in a script or example
**Cause:** mixing forward slashes into a Windows path string manually
instead of using `pathlib.Path` throughout.
**Fix:** every path in this project's Python code uses `pathlib.Path`
(see `src/aisets/config.py`'s `data_dir`) — if you add new paths, do the
same; avoid raw string concatenation for paths.

---

### 18. Python version too old / dependency install fails
```
ERROR: Package 'aisets' requires a different Python: 3.9.x not in '>=3.11'
```
**Cause:** an older Python is on PATH ahead of a newer install.
**Fix:** `python --version` to check; install Python 3.11+ from
python.org and ensure it's first on PATH, or explicitly invoke `py -3.12`
when creating the venv in `scripts\setup.ps1`.
