## Narrative

**As** Northwind's operations team
**I want** every counterparty document we receive stored exactly as it arrived, before anything reads it
**So that** when a parsing bug is found next month we can reprocess the original rather than ask the counterparty to resend, and so that any number in a report can be traced back to the page it came from.

## Why this is first

Nothing downstream is safe to build until the original document is somewhere durable. If extraction runs before landing, a bug in extraction loses the document. Hem's phrasing in design review: *"What does this look like when it's wrong? If it's wrong and we still have the PDF, it's an afternoon. If it's wrong and we don't, it's a phone call to a broker."*

## Acceptance criteria summary

1. A PDF arriving by SFTP or the mail-rule drop lands at `raw/{broker}/{yyyy-mm-dd}/{filename}.pdf` in ADLS Gen2.
2. The `raw/` container is write-once. An existing blob is never overwritten by a later arrival.
3. Landing computes the **SHA-256 of the file content** and records it in the ingestion ledger. Identity is the content, never the filename.
4. A blob landing enqueues exactly one analysis message on the `doc-analysis` queue.
5. A document whose content hash already exists in the ledger is recorded as a resend and does **not** enqueue a duplicate analysis.
6. Nothing in this story reads, parses, or interprets the PDF.
7. Landing failures are visible: a file that cannot be written raises an alert, and the file is not silently dropped.
8. No credentials in configuration. Storage access is by managed identity with the `Storage Blob Data Contributor` role.

## Notes

- The `{yyyy-mm-dd}` in the path is the **arrival** date, not the statement date. The statement date is not known until extraction, and a path that depends on extraction is a path you cannot write before extraction.
- Retention was open at the time of writing (PRD Q2) and resolved on 2026-07-06: seven years, cool at 90 days, archive at 365. Lifecycle policy added under NWD-101 rather than a new story.
- v1.1 (2026-07-24): criterion 5 added after Ravi found that the mail-rule drop re-delivers on retry. This is the same class of problem as [NWD-140](../bug-NWD-140.md), found earlier and cheaper.
