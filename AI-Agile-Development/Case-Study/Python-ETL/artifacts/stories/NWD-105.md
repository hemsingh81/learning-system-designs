## Narrative

**As** Northwind's compliance function
**I want** personal information found and masked before any extracted text is written anywhere downstream
**So that** a nominee account holder's name and address do not end up in a warehouse table that forty people can query, and so that our answer to "where does PII live in this system" is a short one.

## Acceptance criteria summary

1. Extracted text passes through Azure AI Language PII detection before it is persisted to silver, gold, or the exception queue.
2. Detected entities in the categories agreed with Northwind compliance (person name, address, phone, email, national identifier) are masked in place.
3. **Redaction fails closed.** If the PII detection call errors or times out, the raw text is not persisted. A marker is written in its place and the document goes to review.
4. The `raw/` PDF and the `bronze/` extraction response are exempt — they are the immutable originals, are access-restricted, and are lifecycle-managed. Nothing outside the pipeline identity can read them.
5. Redaction never touches the fields the pipeline keys on: account number, security identifier, quantity, price, dates.
6. `redact_pii` is configurable per counterparty and defaults to `true`. A counterparty cannot be onboarded with it off by accident.
7. The count of entities redacted per document is logged, without the entity values.

## Notes

- Criterion 3 is the one people argue about, because failing closed means a Language service outage stops the pipeline. That is the intended behaviour. The alternative is a Language service outage silently writing unredacted names into a warehouse for the duration of the incident, which nobody would notice for a week.
- Criterion 4 is deliberate and was signed off by Northwind compliance on 2026-06-25. Bronze exists precisely so a parsing bug can be reprocessed without re-paying per page, and a redacted bronze cannot serve that purpose.
- The account number is PII-adjacent and is not redacted, because it is the reconciliation key. It is masked in the exception queue UI display instead — the last four digits show. That is Ji-woo's problem, not this story's.
