## Narrative

**As** the recs team lead at Northwind
**I want** a document that is processed twice to produce the same rows as a document processed once
**So that** a retry after a transient failure, a reprocess from bronze, or a counterparty resending yesterday's statement under a new filename does not turn into a data quality incident I have to explain.

## Acceptance criteria summary

1. Canonical rows are written to `silver.counterparty_position` in Azure SQL by **MERGE, never INSERT**, on natural key `(content_hash, line_no)`.
2. Rows are written to `GOLD.COUNTERPARTY_POSITION` in Snowflake by staging into `GOLD.STG_COUNTERPARTY_POSITION` then MERGE. Never a direct INSERT into the target.
3. **Identity is the SHA-256 of the document content, never the filename.** Counterparties resend the same statement under new names constantly.
4. A document's silver rows and its ingestion-ledger entry commit in one transaction, or neither does.
5. Re-running the same document converges on the same rows. Running it three times produces the same table state as running it once.
6. `MIN_CONFIDENCE` and `BRONZE_PATH` are carried onto the warehouse row and are not dropped in the gold load.
7. Snowflake authentication is key-pair (JWT), with the private key held in Key Vault and read by the Function's managed identity. No password anywhere.
8. If Snowflake is unavailable after silver has loaded, silver rows stand and the gold load retries. A partial pipeline does not roll back correct work.
9. Load counts are logged per document: rows written, source key, content hash.

## Notes

- **v1.1, 2026-07-09.** [NWD-140](../bug-NWD-140.md): a resent statement created a duplicate row because one code path — the manual reprocess entry point — hashed the filename rather than the content. The rest of the pipeline was correct. Criterion 3 was in the story from day one; a single function was not holding to it. The fix moved hashing behind one function in `core/idempotency.py` so there is no second path to get wrong.
- Criterion 8 is deliberate asymmetry. Silver and gold are not one transaction and cannot be. The design accepts a window where silver is ahead of gold and makes the gold load converge rather than trying to make the two atomic.
